# 前端表格规范差异报告

> 日期：2026-08-15  
> 对照基准：`.cursor/rules/前端表格规范.mdc`（本仓库适配版）+ `.cursor/rules/列表表格实现说明.md`  
> 对照范围：`ls-aegis-web` 现网列表（`GiTable` / 列定义 / `ColumnSetting`）  
> 结论：**规范已入库，实现未落地；现网与规范冲突项以 `scroll.x:'100%'` 与直连 `GiTable` 为主。**

## 1. 总览

| 维度 | 规范要求 | 现网状态 | 差异等级 |
|---|---|---|---|
| 规则文档 | `前端表格规范.mdc` + 实现说明 | **已有**（本仓库命名） | 无 |
| 档位常量 `TableCol` | `src/constant/table-col.ts` | **缺失** | 高 |
| 归一化工具 | `normalizeTableColumns` / `mergeTableScroll` | **缺失** | 高 |
| 表格壳 `BaseTable` | 列表统一入口 | **缺失** | 高 |
| 底层 `GiTable` | 工具栏/分页/列设置 | **已有** | 无（可复用） |
| `scroll.x` | 数字 = 列宽总和 | **23 处** 使用 `'100%'`（多配 `minWidth`） | 高 |
| 列宽策略 | 每列明确 `width`（px） | 混用 `width` / `minWidth` / `maxWidth` / 无宽 | 高 |
| 列角色档位 | 业务只选 `TableCol.*` | 各页手写像素，无统一档位 | 中 |
| 默认 `align: center` | 归一化补齐 | 仅部分列手写 `align` | 中 |
| 禁止绕过壳 | 禁止直连 `GiTable`/`a-table` | 列表几乎全部直连 `GiTable`；另有 `a-table` | 高 |

**合规粗算（相对规范落地清单 5 项）：规则文档 1/5 完成；代码落地 0/5。**

## 3. 核心原则逐条对照

### 3.1 所有列最终都有明确 `width`（px）

| 现网现象 | 示例 |
|---|---|
| 大量 `minWidth`，无 `width` | 用户管理：昵称/用户名/部门/角色/手机等 |
| 使用 `maxWidth`（规范未采用） | 公告：标题 `maxWidth: 180`，状态 `maxWidth: 100` |
| 名称/短列完全不写宽 | 租户：名称、套餐、状态、描述无 width |
| 序号等用 `minWidth: 66` | 操作日志等 |

→ 宽屏下 Arco 易把剩余宽度均分进弹性列，**名称/短列被拉宽**，与「右侧留白」目标相反。

### 3.2 `scroll.x` = 各列 width 之和（数字）

现网统一模式：

```ts
:scroll="{ x: '100%', y: '100%', minWidth: N }"
```

### 3.3 列四类角色

| 角色 | 规范写法 | 现网常见写法 | 差异 |
|---|---|---|---|
| 操作 | `dataIndex:'action'` + `TableCol.action*`，壳补 `fixed:right` | 多数手写 `width:160` + 条件 `fixed` | 有操作列，但宽度未档位化；壳未统一补固定 |
| 短列 | `width: TableCol.status/date/...` | 状态常无 width 或 `maxWidth`；时间多 `width:180`（接近档位 178） | 未统一 |
| 编号 | `minWidth: TableCol.code*` + `ellipsis:false` → 锁 width + nowrap | 编码多直接 `width`/`minWidth`，且常 `ellipsis:true` | 易截断，无 nowrap 锁 |
| 名称 | 不写 width → 默认锁 240 | 不写宽或 `minWidth`/`maxWidth`，在 `x:100%` 下被拉宽 | 高 |

### 3.4 默认 `align: 'center'`

现网仅部分列显式 `align: 'center'`（序号、状态、操作等），其余依赖组件默认（多为左对齐）。无归一化补齐。

### 3.5 统一走 `BaseTable`

- 业务列表：**0** 处 `BaseTable`，**20+** 处直连 `GiTable`。
- 另：`MultipartUpload/index.vue`、`UserSelect` 内嵌表等使用 `a-table` / `GiTable`（上传分片等非标准列表可评估豁免，但规范字面禁止绕过）。

## 4. 与禁止项对照

| 禁止项 | 现网 |
|---|---|
| ❌ `scroll.x: '100%'` | **普遍存在**（见 §3.2） |
| ❌ 默认自动测宽布局 | 未做单元格测宽；但 `minWidth` + 无 width + `x:100%` 效果接近「弹性吃宽」 |
| ❌ 名称列吃光剩余宽度 | **存在**（租户名称/套餐、用户昵称等） |
| ❌ 编号 ellipsis 截断或过窄换行 | 多页对编码/用户名开启 `ellipsis: true` |
| ❌ 百分比列宽 | 未发现列 `width: 'xx%'`；问题在 `scroll.x` 百分比 |
| ❌ 绕过 BaseTable / 归一化 | **全部列表绕过**（因壳不存在） |

## 5. 列设置（ColumnSetting）差异

| 规范点 | 现网 |
|---|---|
| 支持「重置」清旧 width | 有「重置」：清 `localStorage` 并恢复原始列 |
| 宽度以业务 / normalize 后 props 为准 | 合并为 `localCol.width \|\| col.width`：本地有值则优先本地；改档位后若用户未重置，**旧 width 会盖住新 props** |
| 与 `BaseTable` 协同 | 无；列设置直接挂在 `GiTable` |

→ 落地 `BaseTable` 后建议：列设置只持久化显隐/顺序/固定，**宽度始终跟 normalize 后的 props**（或重置时强制丢掉缓存 width）。

| 项 | 状态 |

## 9. 结论

1. **文档**：`前端表格规范.mdc` 已按本仓库命名适配，可指导后续开发。  
2. **代码**：缺少 `TableCol` / `tableHelper` / `BaseTable`；列表仍直连 `GiTable`，并以 `scroll.x:'100%'` + 分散像素为主。  
3. **冲突面**：至少 **23** 处滚动配置与规范硬禁止项直接冲突；列宽语义（`minWidth`/`maxWidth`/无宽）与「全列锁 width」原则不符。  
4. **建议下一步**：先落地三件套基础设施，再以 1～2 个系统列表作样板迁移，确认观感（右侧留白、编号不截断）后再批量替换其余页面。
